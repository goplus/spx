# 动画绑定音频说明

本文档说明 SPX 中动画绑定音频的生命周期，尤其是 `onStart` / `onPlay` 两种配置在动画循环和动画停止时的行为。

## 背景

动画绑定音频用于把声音直接挂到动画配置上，让声音跟随动画生命周期自动触发。

这类能力常见于：

- 走路动画绑定脚步声
- 挥手/攻击动画绑定起手音效
- 循环动作绑定环境或持续类音效

## 配置入口

动画配置位于 sprite 的 `fAnimations` 中，支持：

```json
{
  "walk": {
    "frameFps": 12,
    "frameFrom": 1,
    "frameTo": 8,
    "onStart": {
      "play": "step"
    },
    "onPlay": {
      "play": "grassWalk"
    }
  }
}
```

其中 `onStart` 和 `onPlay` 现在只需要配置 `play`，不再需要也不再建议配置 `loop`。

## 语义约定

### `onStart`

- `onStart` 固定为非循环 one-shot，不需要配置 `loop`
- `onStart` 会在每次动画开始时触发一次 one-shot 音效
- 如果动画本身是循环播放的，那么每次进入新一轮循环，都视为一次新的动画开始，因此会再次触发一次 `onStart`

适合的场景：

- 每轮动作起点都需要一个短提示音
- 每轮脚步节奏点都要打一个非循环音效

不适合的场景：

- 希望声音持续播放并跨越多个动画周期

### `onPlay`

- `onPlay` 固定为随动画周期重启的循环音效，不需要配置 `loop`
- `onPlay` 会在每次动画开始时启动一个循环音效
- 当动画进入下一轮循环时，上一轮 `onPlay` 音效会在边界被截断，并从头重新开始
- 如果单轮动画周期长于音频长度，音频会在该周期内自行循环
- 如果单轮动画周期短于音频长度，音频会在下一轮开始前被截断

适合的场景：

- 走路、奔跑、滑行这类“只要动作还在就应该持续响”的声音
- 需要严格跟随动画周期边界重启的循环音效

## 动画停止时的行为

这是 `#1376` 关注的重点。

当前约定如下：

- 由 `onPlay` 启动的当前循环音效，会在动画停止时自动停止
- `stopAnimation(...)`、动画自然结束、动画被其他动画替换，都会停止当前 `onPlay` 音效
- `onStart` 是 one-shot 音效，已经触发出去的那一声不会被强制追回；它会自然播放完

也就是说：

- 如果“声音必须跟着动画一起停”，应该放在 `onPlay`
- 如果“声音只是动画开始时打一声提示”，应该放在 `onStart`

## 与 Issue #1376 的对应关系

`#1376` 描述的问题是：

- 动画结束后，绑定的 walking sound 还在继续播放

按当前语义，这类 walking sound 应归类为 `onPlay` 音效：

- 动画播放时持续响
- 动画停止时自动停
- 下一轮动画开始时重新从头触发

因此，类似“牛走路时的草地脚步/摩擦声”应配置在 `onPlay`，而不是手动长期播放后再依赖动画结束自动回收。

## 什么时候不要用动画绑定音频

如果你的目标是下面这些行为，就不建议使用动画绑定音频，而应在脚本里手动控制 `play` / `stop`：

- 声音需要跨越动画结束后继续播放
- 声音生命周期和动画不同步
- 声音是否停止取决于更复杂的游戏逻辑，而不是动画本身

## 手工验证示例

仓库里提供了手工示例：

- `test/AnimationOnStartOnPlayAudio`

可以重点验证：

- `onStart`：每次动画周期开始时触发一次非循环音效
- `onPlay`：每次动画周期开始时启动一个循环音效，并在下一轮边界截断重来
- 动画停止后，`onPlay` 音效应立即停止
